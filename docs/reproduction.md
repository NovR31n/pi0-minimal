# Reproduction guide

This repository makes the implementation, experiment definitions, evaluation
protocol, reports, and compact result tables public. Licensed datasets,
PaliGemma weights, teacher access, checkpoints, cached condition tensors, and
raw rollout media are not redistributed.

The guide separates checks anyone can run from the artifact-dependent steps
used for the reported Student-v3 result.

## 1. Verify the public repository on CPU

Requirements: Git, Python 3.11, and
[`uv`](https://docs.astral.sh/uv/getting-started/installation/).

```bash
git clone https://github.com/NovR31n/pi0-minimal.git
cd pi0-minimal
uv sync --extra dev
uv run --frozen python scripts/validate_model_spec.py
uv run --frozen python scripts/validate_experiment_registry.py
uv run --frozen ruff check .
uv run --frozen python -m pytest -q
```

The tests use a deterministic dummy condition encoder. They exercise tensor
contracts, attention, flow matching, autoregressive sampling, training,
segmented condition caches, metrics, LIBERO adapters, and public-result
consistency without CUDA, datasets, checkpoints, or network model downloads.

The committed JSON and CSV can also be inspected directly:

```bash
python -m json.tool results/student_v3_formal_500_summary.json
```

## 2. Run the real frozen-backbone smoke test

First accept access to `google/paligemma-3b-pt-224` on Hugging Face and provide
a small observation archive generated by `scripts/create_libero_smoke_subset.py`.
Then run:

```bash
uv run python scripts/smoke_paligemma_backbone.py \
  --config configs/model_flow_tiny.toml \
  --data /path/to/libero_smoke_subset.npz \
  --batch-size 1 \
  --device cuda
```

The command prints the frozen parameter count, memory shape, finiteness,
latency, and CUDA memory. It fails if the requested backbone revision, output
dimension, number of image views, or device contract does not match.

## 3. Prepare the LIBERO environment

The verified environment is recorded in [`environment.md`](environment.md).
Install the simulator extra and point Python at a separate LIBERO checkout:

```bash
uv sync --extra dev --extra libero
export PYTHONPATH=/path/to/LIBERO
export MUJOCO_GL=egl
```

Prepare demonstrations and normalization statistics with
`scripts/prepare_libero_data.py`. The resulting arrays, split manifest, and
normalization file belong under `data/`, which is intentionally ignored by
Git. Data shapes and episode-disjoint split rules are documented in
[`data.md`](data.md).

## 4. Re-run Student-v3 training

The accepted continuation launcher is:

```bash
bash scripts/run_student_v3_training.sh preflight
bash scripts/run_student_v3_training.sh formal
```

It requires the following external inputs at the paths encoded in the launcher:

- the 434-episode all-task demonstration dataset;
- the balanced 100-trajectory teacher dataset;
- 39 successful recovery trajectories;
- the accepted Student-v2 initialization checkpoint;
- frozen condition-cache segments for each source;
- the committed split and normalization metadata generated from local data.

The formal run uses seed 7, 10,000 continuation steps, batch size 16, a 50/25/25
demonstration/teacher/recovery mixture, and retains predeclared checkpoint
snapshots. The launcher refuses to overwrite a completed result.

## 5. Re-run checkpoint selection and formal evaluation

Run the staged launchers in order:

```bash
bash scripts/run_student_v3_checkpoint_gate.sh
bash scripts/run_student_v3_validation_gate.sh
bash scripts/run_student_v3_formal_500.sh
```

The final launcher checks that the untouched 90-episode gate passed before it
evaluates the frozen step-10K checkpoint. The formal matrix covers task IDs
0–9 and initial-state IDs 0–49 with seed offset 1000, 220 maximum steps, 10
initial wait steps, five-step replanning, 20-step Euler action sampling, and
256-pixel observations. It audits the identities and checkpoint metadata of
reused frozen-panel episodes before continuing the matrix.

Aggregate a result directory with:

```bash
uv run python scripts/aggregate_rollout_metrics.py \
  --results /path/to/formal-results/task*/init*/result.json \
  --normalization data/libero_spatial_v1/normalization.json \
  --output-csv /path/to/summary/episodes.csv \
  --output-json /path/to/summary/aggregate.json
```

The published outcome is 319/500 (63.8%, Wilson 95% CI 59.5%–67.9%) with zero
exceptions. Against Student-v2 on the same episode identities, the discordant
pairs are 123 V3-only and 53 V2-only (two-sided exact McNemar
`p = 1.371e-7`). See the
[`formal report`](../reports/2026-08-13_student_v3_formal_500.md) and
[`machine-readable summary`](../results/student_v3_formal_500_summary.json).

## Reproducibility boundary

The CPU implementation checks are self-contained after dependency installation.
The numerical benchmark claim is auditable from committed reports and summary
tables, but exact rollout regeneration requires external licensed artifacts and
the same simulator/model revisions. This boundary is deliberate: no private
credentials, gated weights, datasets, or large generated artifacts are placed
in the public repository.
